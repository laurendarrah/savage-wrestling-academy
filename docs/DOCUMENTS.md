# Waivers and contracts

Owner workspace `/documents` manages general waiver/contract drafts, published versions, family assignments and signed records. `/family-documents` lists the current verified family's assigned documents and signed scholarship agreements. `/document-sign?id=...` displays a public shell only; terms and signatures require the assigned family or verified MFA owner. `/document-copy?id=...` provides a private printable signed copy and an HTML download. Browser Print / Save as PDF creates a PDF.

The owner writes or pastes final wording. No legal document is seeded or automatically published. Save a draft before publishing; publication creates an immutable version. Changing a draft or publishing another version does not change existing assignments or signed copies. Archive disables new assignments and publication but preserves existing requests and records. Withdraw affects pending assignments only. Signed assignments cannot be withdrawn or overwritten through the API.

Signing requires verified account ownership, enrolled MFA when applicable, printed full name, a bounded drawn signature, parent/guardian or eligible adult-wrestler role, document acceptance and electronic-signature consent. Youth wrestlers cannot select the adult role. The server records the current UTC timestamp, displayed in New York time. The client cannot backdate it. The signing record retains account email, consent, published-version hash and vector strokes. A conditional D1 batch saves first acceptance and audit evidence together. Requests are scoped to the server-verified user ID, never a client-supplied user ID. Duplicate submissions cannot replace signed evidence.

Migration 0014 appends three D1 tables, `document_templates`, `document_versions`, and `document_assignments`. The hash includes the exact published title, kind and wording. Printable copies verify this hash and the signature metadata before rendering escaped text and bounded signature vectors. Existing scholarship records stay in their original schema and remain accessible from both document areas. No roster sample waiver is imported as a real signature.

Owner assignment selects a saved family wrestler and freezes their name, grade and family contact identity. Signing links require authentication; no email is sent automatically. Families can find requests in their account without the shared link. Owner lists paginate 50 records at a time and support family/email/wrestler/title and status search. The template/family chooser is capped at 500 with an explicit truncation notice. Scholarship summaries show the latest 50 owner matches / latest 100 family records, with the original scholarship area retained.

The legacy backup tool still exports only its legacy data subset. These new tables, scholarship signature records and R2 photos need a complete database/storage backup policy; a legacy backup is not a full system export. Individual signed documents can be downloaded/printed independently. No payment, roster eligibility, attendance check-in, automatic reminders or new legal repayment obligation is triggered by these documents.

Validation `tests/documents.mjs` exercises drafting, publishing, revisions, assignment identity, scope/MFA/origin protection, mandatory signature and consent, replay/tamper handling, immutable copies, filters and archive/withdraw behavior with fictional users and isolated SQLite. Browser form checks use temporary local fictional fixtures that are removed before publication. No live family was assigned or signed by the development checks.

## Parent consent starter

The owner document screen initializes a Parent Consent Form draft with an authenticated same-origin POST. It is added once under the stable `swa-parent-consent` ID. Reopening the page never replaces customized text, revision, archive state or published versions. No schema/data migration, public GET mutation, automatic publication, assignment or signature is used. The owner reviews, edits and publishes it through the normal flow. The existing signing form captures the wrestler, verified account, printed full name, drawn signature, electronic consent and actual server date. Starter wording covers participation permission, safety, restrictions/contact updates, emergency contact and arrival/departure. It excludes purchases, publicity and travel permissions and does not attempt a negligence release. Legal scope was checked against the primary New York source https://www.nysenate.gov/legislation/laws/GOB/5-326 without claiming this draft has attorney approval.

# Page navigation and parent lesson calendar

`public/navigation.js` adds Back and Home controls to the normal full-page HTML screens. Server-rendered family lists, account/security pages and accepted document copies include the same script. Signed-copy scripts use the existing per-response CSP nonce, and navigation is hidden in printed copies. Embedded calendars skip the navigation module so they cannot overwrite their parent page's history.

The module uses native history entries where it can verify an internal predecessor. A per-tab session trail supplies a safe same-origin fallback for direct links, new tabs and auth redirects. Auth callback URLs and sign-in/security steps are omitted from the saved trail to avoid return loops. Sensitive token/code/password query parameters and invite-token hashes are not stored. The trail is limited to 80 entries; state is tab-local and does not grant any access. Existing server account and MFA checks still apply to every protected page/API.

Workspace section changes now create distinct history entries. Browser Back/Forward and the in-page Back control restore the selected section and mode, calendar month, roster filters/search/date, coach selection and published availability selection. Navigation between standalone pages retains these states and the scroll position. Modal Back closes the modal first. Documents retain their records/templates tab, search/status filters and page offset. The parent availability page retains the month, coach and selected date; the public schedule retains its month. Async content restoration retries scroll placement briefly until content arrives, and user interaction cancels that retry.

Only navigation/view metadata is saved. Unsaved form text, passwords, legal agreement wording and signature strokes are not persisted by this module. Saving a form remains necessary before relying on its edits. Server errors/auth gates and off-site destinations retain the browser's normal behavior. If a page has no known internal predecessor, Back returns to a suitable account/home page instead of sending a visitor to an arbitrary external referrer.

The parent private-lesson page now renders a full monthly availability calendar with previous/next month controls, coach filter and selectable dates. Marked dates show the coach and opening time; selecting a date filters the detail cards. The data still comes from actual saved active-coach openings. Booking, payments and refund handling are not enabled by these view changes.

Validation includes tests/navigation.mjs plus the existing application tests. Browser checks use temporary fictional fixtures, removed before build. They exercised workspace section Back, full-page Back, selecting a parent calendar date, leaving the page and returning to the same selected date. No real family account was signed in and no live booking or agreement was submitted. Refund policy was not changed; the current membership terms remain a draft pending final agreement and applicable statutory cancellation rights.
